Resource Hierarchy

Google Cloud resources are organized top-down. Policies set higher up are inherited downward.

LevelPurpose
OrganizationRoot node; tied to a Cloud Identity / Workspace domain
FoldersGroup projects by department / environment; optional
ProjectsThe core trust and billing boundary; all resources live in a project
ResourcesVMs, buckets, databases, etc.
⚠ Exam Tip

IAM policies are inherited and the effective policy is the union of policies at every level. A less restrictive parent policy cannot be overridden by a child. Billing is linked at the project level.

Identity & Access Management (IAM)

Member types

  • Google account (user)
  • Service account (for workloads)
  • Google group
  • Cloud Identity / Workspace domain
  • allAuthenticatedUsers / allUsers (public)

Role types

  • Basic - Owner, Editor, Viewer (avoid in prod)
  • Predefined - granular, per-service (preferred)
  • Custom - you pick exact permissions
💡 Service Accounts

Use service accounts for VM/app identity. Prefer attaching a service account to a resource over downloading JSON keys. Grant the Service Account User role to let a principal act as a service account.

Compute

ServiceBest forKey facts
Compute EngineVMs, full OS controlMachine families (E2, N2, C3); preemptible/Spot VMs for ~60-91% savings; MIGs for autoscaling
GKEContainerized microservicesAutopilot (managed nodes) vs Standard; workload identity for IAM
Cloud RunStateless containers, serverlessScales to zero; pay per request
App EngineWeb apps, PaaSStandard (sandbox) vs Flexible (containers)
Cloud FunctionsEvent-driven glue codeTriggered by HTTP, Pub/Sub, Storage events
💡 Managed Instance Groups (MIGs)

Provide autoscaling, autohealing, rolling updates, and multi-zone deployment. Pair with a load balancer for HA. Know the difference between managed (identical, template-based) and unmanaged instance groups.

gcloud & Tooling

Expect to read and complete gcloud commands. Core patterns:

# Set the active project
gcloud config set project my-project-id

# Create a VM
gcloud compute instances create web-1 --zone=us-central1-a --machine-type=e2-medium

# Grant an IAM role
gcloud projects add-iam-policy-binding my-project-id \
  --member="user:alice@example.com" --role="roles/compute.viewer"

# Deploy to Cloud Run
gcloud run deploy my-svc --image=gcr.io/my-project/img --region=us-central1

# Interact with a GKE cluster
gcloud container clusters get-credentials my-cluster --region=us-central1
kubectl get pods
💡 Know the tools

gcloud (platform), gsutil/gcloud storage (Cloud Storage), bq (BigQuery), kubectl (Kubernetes), and Cloud Shell (browser terminal with tools preinstalled).
